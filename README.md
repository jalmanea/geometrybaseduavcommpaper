# Altitude Selection for Multi-UAV Deployment Under Directional Interference

Code and paper sources for:

> **Altitude Selection for Multi-UAV Deployment Under Directional Interference**
> Abdulrahman Almanea, Balsam Alkouz, and Basem Shihada
> King Abdullah University of Science and Technology (KAUST)

Every figure, table and number in the paper (`paper/main.tex`) can be
regenerated by running the scripts in this repository. No result files are
included: run the experiments first (a few CPU-hours in total, all seeded), then
the figure and number scripts. The telecom part (Fig. 4, Sec. IV-D) also needs
the Telecom Italia Milan dataset, which is not included and must be downloaded
separately.

## The three methods

All three place drones at the K-means centroids of the known user positions
(`scipy.cluster.vq.kmeans2`, `minit="points"`), associate each user with the
nearest drone in 3D, point the userlink antenna at nadir and orient the backhaul
antenna along a minimum spanning tree. They differ only in altitude.

| Method | Name in code and data | Altitude |
|---|---|---|
| K-means baseline | `kmeans` | fixed 150 m |
| Analytic heuristic | `analytic` | per drone, `z = sigma / tan(theta_3dB / 2)` clamped to [50, 300] m, where `sigma` is the spread of the drone's cluster |
| Altitude sweep | `kmeans_altitude_sweep` | one common altitude, the best-coverage value in {50, 60, ..., 300} m |

The deployment functions are in `dronecomm/heuristic.py`
(`deploy_kmeans_baseline`, `deploy_analytic_heuristic`,
`deploy_kmeans_global_altitude_sweep`); the system-model evaluation is in
`dronecomm/optimize.py` (`_build_models`, `_evaluate_single`). The parameters of
Table I are the defaults in `dronecomm/config.py` and `configs/default.yaml`.

## Installation

```bash
git clone https://github.com/jalmanea/geometrybaseduavcommpaper
cd geometrybaseduavcommpaper
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pytest -q            # 67 tests
```

or `conda env create -f environment.yml && conda activate dronecomm`.

Tested with Python 3.13.5, numpy 2.3.1, scipy 1.16.1, pandas 2.3.2 and
matplotlib 3.10.5 on macOS (arm64); `requirements-tested.txt` pins these for
pip, and the header of `environment.yml` gives the exact conda command. The
code also runs, and prints the same numbers, with the newest releases
(numpy 2.5, scipy 1.18, pandas 3.0, matplotlib 3.11).

What to expect from a rerun, compared with the runs behind the paper:

- The printed numbers were identical in every environment we tried.
- Telecom results were reproduced bit for bit in our checks (same snapshots,
  same seeds).
- Synthetic results agree to floating-point rounding (coverage within 2e-14
  percentage points, other metrics within 1e-11), not bit for bit: the paper's
  K-means and analytic runs were computed on a Linux cluster.
- Figs. 2-4 come out byte-identical to the PNGs in `paper/figures/` only with
  the conda build of matplotlib 3.10.5 (FreeType 2.13.3). The pip wheel bundles
  FreeType 2.6.1, which shifts text by a pixel or two; the plotted data are the
  same.
- Build times are wall-clock measurements and depend on the machine, so
  `paper_numbers.py` will report the four build-time values (2.3, 5.0 and
  135 ms, 0.91 s maximum) as mismatches on a rerun.

Run every script from the repository root. The experiment scripts put the
repository root first on `sys.path`, so they use this repository's `dronecomm`
even if another copy is installed.

experiment scripts also evaluate methods that the paper does not report
(`analytic_pca`, `repulsive_lloyd`, `altitude_stagger`); the figure and number
scripts ignore them.

## 1. Running the experiments

CPU times are single-core totals on an Apple M-series laptop. All runs are
seeded, so the tasks can be executed in any order and in parallel.

### Synthetic K-means and analytic results (up to about 2 CPU-h)

1,500 configurations (N = 1..50, M = 100..1000, three distributions), 20 seeds
each (1000..1019):

```bash
for i in $(seq 0 1499); do
  python scripts/run_heuristic_experiment.py --task-id $i \
      --drone-counts $(seq 1 50) --no-greedy --output results/heuristic_50
done
```

SLURM: `sbatch --array=0-14 scripts/submit_heuristic_50.sh --no-greedy`.

This also writes a `kmeans_altitude_sweep` entry per file; the paper's sweep
numbers are read from the dedicated run below instead.

### Synthetic altitude sweep (about 70 CPU-min)

```bash
python scripts/run_altitude_sweep_addition.py --out results/sweep_addition   # --procs 8 by default
```

### Telecom Italia data and snapshots (needed for the telecom rerun)

The Telecom Italia Milan dataset is protected by its own licence and copyright.
Neither the dataset nor anything derived from it is included in this repository. Fig. 4, the Sec. IV-D
numbers and `paper_numbers.py --altitudes` therefore require downloading the
data and running the two steps below (about a minute for the snapshots and
1.8 CPU-h for the results).

Download the files below yourself (the Dataverse asks for a guestbook form) and
put them in `dataverse_files_milan/` at the repository root. That directory and
`results/telecom_milan/` are git-ignored and must not be committed.

- Activity: Harvard Dataverse, [doi:10.7910/DVN/EGZHFV](https://doi.org/10.7910/DVN/EGZHFV)
- Grid (reference only, not read by the scripts): [doi:10.7910/DVN/QJWLFU](https://doi.org/10.7910/DVN/QJWLFU), `milano-grid.geojson`

```bash
python scripts/extract_telecom_snapshots.py   # defaults: --region milan --data-dir dataverse_files_milan

```

This writes 24 `snapshot_*.npy` files (800 sampled user positions each) and
`snapshot_metadata.json` to `results/telecom_milan/snapshots/` in about a
minute. The extraction is seeded and reproduces the snapshots used in the paper
bit for bit.

### Telecom results (about 1.8 CPU-h)

Requires the snapshots from the previous step.

24 snapshots x 26 fleet sizes x 8 user counts = 4,992 tasks, 20 seeds and three
methods each:

```bash
for i in $(seq 0 4991); do
  python scripts/run_telecom_statistical.py --phase main --task-id $i \
      --snapshot-dir results/telecom_milan/snapshots \
      --drone-counts $(seq 5 30) --user-counts $(seq 100 100 800) \
      --n-seeds 20 --no-greedy \
      --methods kmeans analytic kmeans_altitude_sweep \
      --output-dir results/telecom_milan
done
```

SLURM: see the header of `scripts/submit_telecom_statistical_batched.sh`
(50 array slots of 100 tasks). The script's built-in defaults for user counts,
seeds and methods belong to an earlier design; pass the flags shown.

### UL orientation check (about 3.6 CPU-h for the sweep method alone)

36 tasks (N in {5, 10, ..., 30}, M in {200, 400}, three distributions), 5 seeds:

```bash
for i in $(seq 0 35); do
  python scripts/run_per_drone_angle_sweep.py --task-id $i \
      --distributions clustered hotspot uniform \
      --drone-counts 5 10 15 20 25 30 --user-counts 200 400 --n-eval-seeds 5 \
      --no-grids --methods kmeans analytic --output results/angle_sweep/run_46540284
  python scripts/run_per_drone_angle_sweep.py --task-id $i \
      --distributions clustered hotspot uniform \
      --drone-counts 5 10 15 20 25 30 --user-counts 200 400 --n-eval-seeds 5 \
      --no-grids --methods kmeans_altitude_sweep --output results/angle_sweep/run_local_altsweep
done
```

SLURM: `sbatch --array=0-35 scripts/submit_per_drone_angle_sweep.sh <same flags>`.

`--no-grids` leaves the per-drone coverage grids out of the output (about
335 MB otherwise); the paper's numbers do not use them. The two output
directory names are the ones `paper_numbers.py` reads.

## 2. Figures and numbers (about a minute, once the results exist)

```bash
# Figs. 2-3 (PDF and PNG) into paper/figures/, and Fig. 4 if the telecom
# results exist
python scripts/plot_sweep_addition_figures.py

# Sec. IV-B, IV-C, abstract and conclusion: every number, checked against the paper text
python scripts/paper_numbers.py

# Sec. IV-D (telecom) numbers
python scripts/telecom_numbers.py

# Optional (~1 min more): also recompute the altitudes quoted in the text,
# which are not stored in the result files (needs the Milan snapshots)
python scripts/paper_numbers.py --altitudes
```

`paper_numbers.py` prints each computed value next to the value quoted in the
paper and exits non-zero if any differ.

To build the paper (6 pages, IEEEtran):

```bash
cd paper && pdflatex main && bibtex main && pdflatex main && pdflatex main
```

With `tectonic` (XeTeX), add `\usepackage[T1]{fontenc}` to a temporary copy
first, otherwise the bold and Times fonts are lost.

## Repository layout

```
dronecomm/     simulation library (antenna, channel, SINR, deployment heuristics, evaluation)
configs/       default parameters (Table I)
scripts/       experiment, extraction, plotting and number-printing scripts, SLURM wrappers
results/       created by the experiment scripts (git-ignored)
tests/         unit tests
paper/         main.tex, references.bib, figures/
```

`scripts/plot_environment_figure.py` and `notebooks/` belong to an earlier
version of this work. They are kept for reference and are not needed to
reproduce the paper; the notebooks expect result sets that are not shipped here.
